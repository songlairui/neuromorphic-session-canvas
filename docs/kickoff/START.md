# neuromorphic-session-canvas · 缘起

## 当初为什么要做这件事

我同时开着一堆 agent 会话和项目，每个会话都在各自的侧边栏里排队等我。问题不是数量，是**注意力**：传统线性历史列表要求我一个个扫过去才知道"现在谁在等我"。活跃的、等我拍板的、早就冷掉的，全被压成一排相同的行。

脑科学里位置细胞记的是**空间位置**，人对空间关系的记忆远好于对时间序列的记忆。所以想把会话从"时间轴上的行"挪到"空间里的建筑"：每个项目是一座岛，每个会话是一栋楼，状态不靠文字标签而靠视觉显著性——活跃的会话亮着光环占据高地块，冷掉的自动缩微隐入地平线。空间注意力替代线性扫描。

## 关键取舍

- **MVP 视觉用 DOM + CSS 3D 变换，不上 WebGL**。等轴矩阵配合 Tailwind 和拖拽缩放就能起步，还和 DOM UI（抽屉面板、徽章）无缝结合。以后渲染不够再上 Canvas/WebGL。
- **契约先行**：oRPC router + mock 数据先落，UI 后接。岛屿（Island）与会话节点（SessionNode）的数据模型已按沙盘语义设计好。
- **技术栈**：TanStack Start（Nitro/Vite 全栈 React）+ oRPC + Tailwind v4 + shadcn/ui + Lucide，暗色沙盘风格。

## MVP 范围（按原始规格）

1. 等轴视口：平移 / 缩放 / 归中到活跃任务，等轴网格对齐
2. 岛屿地块立体厚度 + 标牌；会话建筑悬浮预览，双击展开侧边会话面板
3. 一键在岛屿上新建会话；右下角小地图定位远端岛屿
4. 状态视觉反馈：active / waiting_user 高显著，idle / archived 弱化

## 后续半年回看时可能问的问题

- 为什么不用现成的 node-graph 或 force-directed 库？因为我们要的是**固定的等轴城市感**而不是力导向图。
- 等轴投影选 dimetric（2:1 菱形）而非真 30°——DOM 里好做、好拖拽，视觉损失可接受。
- 会话"建筑"的具体形态（立方体高度？屋顶色？）还没定，先用等轴方块 + 状态光环。
